## Identifiers

- Y-tunnus: the mod-11 check digit (weights 7, 9, 10, 5, 8, 4, 2) is valid for every business.
- IBAN: FI, 18 characters. The BBAN's last digit is a Luhn check and the IBAN check digits are mod 97.
  The bank-group digits are not asserted to belong to any real bank.
- Viitenumero: the 7-3-1 check digit, grouped in fives from the right.
- Henkilötunnus: a valid mod-31 check character, using individual numbers **900–999**. That range
  is reserved for test and temporary IDs and is never assigned to real people.
- Bank lines carry a deterministic archive ID (`YYMMDDKSYPnnnnnn`). Invoices carry a
  version-4 virtual barcode that encodes the IBAN, amount, reference and due date.

## Rebuilding

```bash
pip install -r scripts/fixtures/fi_synthetic_remontti/requirements.txt
python3 scripts/fixtures/fi_synthetic_remontti/build.py          # rewrite sources/, README.md, SHA256SUMS
python3 scripts/fixtures/fi_synthetic_remontti/build.py --check  # rebuild in a temp dir and compare with SHA256SUMS
```

- `scenario.py` is the **one data file**: parties, documents, lines, dates, the bank schedule and the payroll inputs.
- `model.py` computes VAT, payroll, interest, bank lines and the key's journals, then **refuses to build** if anything
  fails to reconcile. It checks every check digit; net + VAT = gross on every document; balanced journals; each bank
  line's 1910 leg equal to the statement amount; both statements chaining opening → closing with weekday dates; the
  trial balance at 31.8. and 30.9.; payslip net equal to the salary line; the TyEL invoice equal to the accrued amount;
  the 30.9. balances of payroll liabilities, receivables, the card and the owner receivable; reverse-charge tax equal to
  its deduction; output VAT recomputed independently from the sales documents; and section C's ALV due equal to the
  open ALV positions.
- `render.py` / `key.py` render the documents and the answer key. The build also fails if a PDF uses a character the
  embedded font cannot draw.
- Output is byte-identical between runs: reportlab runs in invariant mode, only fonts shipped inside reportlab are
  used, and every photo effect comes from a seeded RNG. Byte identity holds for the pinned versions in
  `requirements.txt`. Other reportlab or Pillow versions can produce different bytes for the same content.
